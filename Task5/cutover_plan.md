# Cutover Plan: Миграция системы «Медикаменте»

## 1. Выбор стратегии миграции

### 1.1. Рассмотренные стратегии

| Стратегия | Описание | Преимущества | Недостатки |
|-----------|----------|--------------|------------|
| **High-level design** | Полная остановка старой системы, запуск новой | Быстрая миграция, нет дублирования | Высокий риск простоя, нет отката |
| **Parallel run** | Параллельная работа старой и новой систем | Минимальный риск, постепенный перевод | Двойная нагрузка, синхронизация данных |
| **Branch by abstraction** | Постепенная замена слоёв через абстракции | Гибкость, итеративность | Сложность, длительное время |

### 1.2. Выбранная стратегия: **Parallel Run**

**Обоснование выбора:**

Для медицинской компании «Медикаменте» выбран подход **Parallel Run** (параллельный запуск) по следующим причинам:

**Преимущества для данного сценария:**
1. **Минимальный риск для бизнеса** — старая система продолжает работать, новая тестируется на реальных данных
2. **Постепенный перевод пользователей** — можно мигрировать по отделам (ресепшен → врачи → бухгалтерия)
3. **Возможность отката** — при проблемах быстро возвращаемся к старой системе
4. **Валидация данных** — сравнение результатов в обеих системах
5. **Обучение без давления** — персонал учится на новой системе без остановки работы

**Ограничения:**
- Двойная инфраструктура (стоимость на 2-3 месяца)
- Необходимость синхронизации данных между системами
- Дополнительная нагрузка на персонал (ввод в две системы)

**Почему не другие стратегии:**
- **High-level design** — слишком высокий риск простоя для медицинской организации
- **Branch by abstraction** — слишком сложно для миграции Excel/1С → микросервисы

## 2. Cutover-план

### 2.1. Обзор этапов миграции

| Этап | Недели | Длительность | Описание |
|------|--------|--------------|----------|
| **1. Подготовка** | 1-2 | 2 недели | Развёртывание инфраструктуры, настройка окружений, синхронизация |
| **2. Миграция данных** | 3-4 | 2 недели | Экспорт из Excel, очистка, импорт в PostgreSQL, валидация |
| **3. Тестирование** | 5-6 | 2 недели | Функциональное, нагрузочное, безопасность, UAT |
| **4. Обучение** | 6 | 1 неделя | Обучение всех отделов (ресепшен, врачи, бухгалтерия, склад) |
| **5. Пилотный запуск** | 7-8 | 2 недели | Запуск для ресепшена, параллельный ввод, мониторинг |
| **6. Полный запуск** | 9-10 | 2 недели | Запуск для всех отделов, параллельная работа |
| **7. Завершение** | 11-12 | 2 недели | Валидация, отключение старой системы, архивация, пост-мортем |
| **Итого** | **1-12** | **12 недель** | **Полная миграция системы** |

## 5. План отката (Rollback Plan)

### 5.1. Критерии для отката

Откат выполняется при одном из следующих условий:
- Критическая потеря данных (>1% записей)
- Простой системы > 4 часов без возможности восстановления
- Критическая уязвимость безопасности
- Массовое сопротивление персонала (>50% пользователей)

### 5.2. Процедура отката

| Шаг | Действие | Время | Ответственный |
|-----|----------|-------|---------------|
| 1 | Объявление режима отката | 5 минут | IT-директор |
| 2 | Остановка новой системы | 10 минут | Администратор сети |
| 3 | Переключение на старую систему | 15 минут | Администратор сети |
| 4 | Восстановление данных из бэкапа | 30 минут | Бизнес-аналитик |
| 5 | Проверка работоспособности | 30 минут | Все участники |
| 6 | Уведомление пользователей | 15 минут | Бизнес-аналитик |
| 7 | Пост-мортем инцидента | 2 часа | IT-директор |

**Общее время отката:** ~2 часа

### 5.3. Точки отката

| Этап | Точка отката | Состояние системы |
|------|--------------|-------------------|
| Подготовка | До недели 3 | Старая система работает |
| Миграция данных | До недели 5 | Старая система + бэкап данных |
| Тестирование | До недели 7 | Старая система работает |
| Пилотный запуск | До недели 9 | Параллельная работа, откат для пилотной группы |
| Полный запуск | До недели 11 | Параллельная работа, полный откат |
| Завершение | После недели 11 | Откат невозможен (старая система отключена) |

## 9. Выводы

### 9.1. Итоги планирования

Разработан детальный cutover-план миграции системы «Медикаменте» с использованием стратегии **Parallel Run**. План включает:

- **7 этапов миграции** на 12 недель
- **38 задач** с назначенными ответственными
- **8 ключевых рисков** с мерами снижения
- **План отката** со временем восстановления 2 часа
- **Критерии успеха** (технические и бизнес)
- **Коммуникационный план** для всех стейкхолдеров

### 9.2. Ключевые факторы успеха

1. **Параллельная работа систем** — минимизация риска простоя
2. **Поэтапный запуск** — сначала пилот (ресепшен), потом все отделы
3. **Двойной ввод данных** — валидация корректности миграции
4. **Готовность к откату** — план действий при критических проблемах
5. **Обучение персонала** — снижение сопротивления изменениям
